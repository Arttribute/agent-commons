# Production readiness status

This is the working release record for the Desktop, Web, Cloud, and Private Local continuity work. A passing local smoke test does not establish a production release.

## Implemented and locally checked

- New chats render the sent message immediately; title generation, steering, and stream reconnection paths are wired in both modes.
- The composer exposes provenance and Local web search in its add menu, uses the Knowledge brain icon, and shows a removable workspace folder. A user can configure Brave Search with their API key or a SearXNG endpoint from the chat without navigating to Settings; every outbound query still asks for approval. The selected search state is saved immediately for an existing Local conversation, and configured SearXNG paths such as `/searx` are retained. Changing providers clears the key in the form; changing the endpoint separately clears its stored key. Turning search off during a run removes the tool on the next model step and stops a query even if an approval dialog was already open; the Desktop smoke test covers that revocation.
- Projects have their own navigation, bounded scroll areas, document preview, folder import to Library, and tools for finding and reading other chats in the same project.
- Local agents can select downloaded Ollama chat models. Whisper speech input, SpeechT5 spoken output, and a default Tiny SD image model run on device. General Settings now offers one-click, checksum-verified Q4 and Q8 versions of Tiny SD. The Q4 model downloaded and generated a PNG on macOS ARM. An optional Kokoro voice model and four voices are selectable in General settings; its cached inference generated audio in a local Node smoke test.
- Local and Cloud file uploads accept files up to 25 MB in the UI path. Cloud browser uploads use short-lived, single-use, signed direct-upload tickets to avoid the Next.js body proxy. Local and CLI document reads return bounded chunks with offsets so a large PDF does not consume the entire model context. `cli_search_file` and `search_library_item` find bounded passages and offsets in large workspace and attached/project Library files; repeated workspace PDF reads reuse an in-memory extraction cache. Desktop smoke journeys located and read conclusions near the end of both a long workspace file and an attached Library file. A 2.2 MB, 180-page PDF yielded 691,477 characters in a local extraction stress check; the Cloud extraction default now covers 500 pages and one million characters, and flags a partial extraction.
- Desktop tool execution now retains the login-shell command path and supports background CLI processes. A real Local model fixed a JavaScript function, ran Node to verify it, and read a 2.2 MB PDF in the scripted smoke journey.
- A separate real Qwen 3 1.7B run fixed the function but failed to verify its result and did not read the PDF successfully. Its attempt exposed a macOS `/var` path alias issue in the CLI file boundary; canonical path validation now accepts that alias while still rejecting paths outside the workspace. The small model is not a reliable choice for this agentic coding and document task.
- A real Qwen 3 4B run on an 8 GB Mac did not finish the same coding plus large-PDF journey within five minutes. It occupied 5.5 GB at a 16k context size and caused heavy memory pressure, so the model catalog now recommends at least 12 GB RAM for this option. The test model was removed afterward to recover disk space; it remains available for users to download through General settings.
- A real Qwen 2.5 Coder 3B run on the same task refused the benign coding and document requests without using tools. It is still an optional code-focused download, but this run does not support choosing it as the default general-purpose agent model. The temporary test download was removed.
- A real Qwen 3.5 2B run initially fixed and verified the JavaScript function but then read the 180-page PDF sequentially until the five-minute test timed out. That trace prompted `cli_search_file` and clearer workspace document guidance. With those changes, the same model fixed the function, verified its result with Node, read the 2.2 MB PDF, and answered its final recommendation in the Desktop stress journey. It is now the default for new Local workspaces on computers with at least 8 GB RAM; Qwen 3 1.7B remains the low-memory default. Existing model choices remain respected.
- Cloud run events, steering, and CLI result handoff now use Postgres across API replicas. A run is registered in the shared store before inference begins; failed registration stops the run. This supports reconnection when the browser reaches a different healthy replica.
- A gated hosted-free model route, usage quota, and credit fallback exist in the API. The free model is hidden until the dedicated inference endpoint is configured and healthy.
- The latest Web and Desktop TypeScript checks, Desktop build, all 40 Desktop unit tests, and Desktop UI/tool smoke test passed after the in-chat Web search and large-document changes. The Desktop smoke also checks that turning Web search off during approval prevents an outbound query and that changing a SearXNG endpoint clears its stored key.
- A dependency audit found critical advisories in the pinned Next.js, Auth.js, and decompression packages. The Web app and Docs now resolve to Next.js 15.5.24; Courses resolves to Next.js 16.3.6; the Auth.js consumers resolve to `next-auth` beta.32 and `@auth/core` 0.41.3; the nested decompression package resolves to 11.1.4. The Local and Cloud MCP SDK resolves to 1.26.0, and Identity uses Better Auth 1.6.22 with matching core/OAuth provider packages. The API's direct Playwright dependency resolves to 1.55.1. Compatible transitive overrides patch Axios, fast-uri, engine.io, protobufjs, PostCSS, tar, and other affected dependencies. Unused API packages were removed; the API and Identity now resolve to Drizzle ORM 0.45.3, and the API and Desktop resolve to patched Sharp binaries. The API uses the vendored official SheetJS 0.20.3 package with its integrity pinned in the lockfile. XLSX, XLS, and ODS round trips, all 16 API file service tests, a Postgres SQL run-store integration test, the Identity build, the Desktop smoke, and a real on-device Whisper tiny inference passed with these changes. The regenerated production lockfile audit reports zero critical and five high advisories. Sources: [Next.js AVIF advisory](https://github.com/vercel/next.js/security/advisories/GHSA-2xp9-vwfh-vxw4), [Next.js ImageResponse advisory](https://github.com/vercel/next.js/security/advisories/GHSA-vcvr-r3jv-pc5j), [Auth.js advisory](https://github.com/nextauthjs/next-auth/security/advisories/GHSA-7rqj-j65f-68wh), [MCP SDK advisory](https://github.com/modelcontextprotocol/typescript-sdk/security/advisories/GHSA-345p-7cg4-v4c7), [SheetJS advisories](https://cdn.sheetjs.com/advisories/).

## Release blockers

1. **Hosted free inference:** The GPU service has not been deployed or load tested. AWS login was refreshed, a $500 monthly account budget was created, and an eight-vCPU G/VT quota increase for `eu-west-2` is pending. The budget does not stop spending by itself. A verified model, cost guard, service deployment, and staging load test are still required. The free model remains hidden. See [hosted-free-model-service.md](./hosted-free-model-service.md).
2. **Durable long runs:** An API worker restart still interrupts its active agent. The shared store replays events and reports interruption; it does not resume execution on a new worker. A durable worker queue and restart recovery are required for the requested very long-running tasks.
3. **Media model choice:** Chat models are selectable; images offer the starter model plus Q4 and Q8 versions of the same Tiny SD architecture, and accept compatible manually installed checkpoints; speech offers Whisper sizes, SpeechT5 voices, and a downloadable Kokoro voice option. Other image architectures and downloadable video generation models are not complete. Local video generation is not implemented.
4. **Platform coverage:** The image and voice runtime has been exercised on macOS ARM. Windows and Linux image binaries and the packaged app need their own end-to-end checks.
5. **Production verification:** The new Cloud run path has unit checks and a two-replica simulation against real Postgres SQL in PGlite. It still needs an authenticated staging journey with real storage, managed Postgres, GPU inference, and simultaneous API replicas. A staging deployment attempted on 30 September failed during its API canary rollout: the account's 12-vCPU Fargate quota was exhausted and the old staging image digest had been deleted. A 16-vCPU quota request is open; ECR retention has been raised from 30 to 120 images in AWS and the bootstrap templates to prevent this deletion on future rollouts. A second update using the already-built `staging-manual-108` images again failed the API canary because the vCPU quota blocked task placement and the old digest is missing. The CloudFormation stack has been recovered to `UPDATE_ROLLBACK_COMPLETE` by skipping the failed staging service resources. The staging API remains at 0/1 running tasks until capacity is increased and a new image can be deployed. The macOS signing identity is expired, so a production signed Desktop release cannot be published yet. An unsigned packaged macOS candidate passed its launch smoke.
6. **Workspace baseline:** A full API typecheck in this working tree currently fails on unrelated untracked `game-thumbnails` and `common-tool.service.spec` files. The production changes typecheck with those files excluded; resolve or isolate that work before a clean release build.
7. **Dependency triage:** The production lockfile audit still reports five high-severity advisories after the critical, direct-exposure, and compatible transitive patches. The remaining paths are `bigint-buffer` through Web wallet authentication, `extract-zip` through the API's Puppeteer browser installer (two advisories), and `image-size` through a React Native/Metro peer path (two advisories). The first two have no patched npm release; the last requires a major upgrade. Each path needs reachability review and a compatible patch, replacement, or documented mitigation before release.

Do not merge or deploy these changes as a complete production release until the blockers above are closed and the exact release artifact passes smoke tests.
