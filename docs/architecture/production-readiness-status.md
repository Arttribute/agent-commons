# Production readiness status

This is the working release record for the Desktop, Web, Cloud, and Private Local continuity work. A passing local smoke test does not establish a production release.

## Implemented and locally checked

- New chats render the sent message immediately; title generation, steering, and stream reconnection paths are wired in both modes.
- The composer exposes provenance and Local web search in its add menu, uses the Knowledge brain icon, and shows a removable workspace folder. A user can configure Brave Search with their API key or a SearXNG endpoint from the chat without navigating to Settings; every outbound query still asks for approval. The selected search state is saved immediately for an existing Local conversation, and configured SearXNG paths such as `/searx` are retained. Changing providers clears the key in the form; changing the endpoint separately clears its stored key. Turning search off during a run removes the tool on the next model step and stops a query even if an approval dialog was already open; the Desktop smoke test covers that revocation.
- Projects have their own navigation, bounded scroll areas, document preview, folder import to Library, and tools for finding and reading other chats in the same project.
- Local agents can select downloaded Ollama chat models. Whisper speech input, SpeechT5 spoken output, and a default Tiny SD image model run on device. General Settings now offers one-click, checksum-verified Q4 and Q8 versions of Tiny SD. The Q4 model downloaded and generated a PNG on macOS ARM. An optional Kokoro voice model and four voices are selectable in General settings; its cached inference generated audio in a local Node smoke test.
- The two automatic Local chat defaults, Qwen 3.5 2B and Qwen 3 1.7B, now require their reviewed Ollama registry manifest digests. Setup downloads the selected model even when other models are already installed, rather than silently selecting the first available model. User-selected alternatives remain available. The Desktop image runtime ZIP extractor now rejects symlinks, duplicate names, escaped paths, unsupported entry types, and oversized archives; it extracted the actual 35 MB SHA-verified macOS runtime archive and rejected a malicious symlink fixture. Desktop TypeScript, build, and all 42 unit tests pass after these changes.
- Automatic Local image generation now chooses the verified Tiny SD Q4 checkpoint on 8–11 GB computers and the full checkpoint on computers with at least 12 GB. General Settings shows the recommendation. Below 8 GB RAM, the app explains the memory requirement before downloading a default image model. Existing model selections remain stored.
- The built-in Whisper and SpeechT5 models now fetch immutable reviewed Hugging Face commits. Their ONNX weights are checked against publisher SHA-256 values before the app marks them ready. SpeechT5's separate vocoder is pinned and checked too. A damaged cached weight is removed before retrying; low free disk space stops a download with a concrete size requirement. The first speech smoke exposed a library behavior that reported success despite a failed cache write; the new checks reject that state. After disk space recovered, a clean pinned SpeechT5 download generated WAV audio, Whisper Base downloaded and passed its saved-weight checks, and a SpeechT5-to-Whisper round trip transcribed “The sky is blue today” as “the sky's blue today.” Desktop typecheck and all 44 tests pass. Sources: [Whisper Base](https://huggingface.co/Xenova/whisper-base), [SpeechT5](https://huggingface.co/Xenova/speecht5_tts), [SpeechT5 vocoder](https://huggingface.co/Xenova/speecht5_hifigan).
- Web sign-in uses Commons Identity. The unused Privy provider had no consumers in the app and pulled in a vulnerable Solana buffer package; removing it and its lockfile tree reduced the production audit from five to four high advisories. Web TypeScript passes after this removal.
- Presentation generation now detects the actual uploaded image format with Sharp and converts WebP and other non-PNG/JPEG artwork to PNG before embedding it. This prevents a PowerPoint slide from declaring PNG while containing incompatible bytes. The image decoder also caps input at 25 million pixels. All 17 file service tests pass, including a mismatched-MIME WebP case.
- A real staging CodeBuild build found that the API Dockerfile omitted the pinned SheetJS archive before `pnpm install` and that the final Wolfi image lacked Chrome's ALSA library. Both were corrected. A subsequent isolated build loaded Sharp and Puppeteer inside the final image and ran Chrome for Testing 152.0.7977.64; its immutable ECR image scan completed with no critical or high findings. That image deployed to the existing staging API service with 100% traffic and a successful ECS canary. The API `/health` endpoint returned 200, the staging database reported zero pending versioned migrations, and an authenticated skill route probe passed. Staging search was restored to one running task and `/healthz` returned 200.
- An authenticated staging CLI coding run initially failed because the agent sent 132 tool definitions to OpenAI, above its 128-tool limit. The API now bounds each model call's catalog, keeps local and configured tools first, and selects relevant platform tools when trimming is needed. The exact patched image passed its final-container Chrome/Sharp check, ECR scan, and ECS canary. A subsequent real GPT-4o mini run used `cli_run_command`, `cli_read_file`, and `cli_write_file` to fix `sum(a,b)` in a disposable workspace, ran Node, and reported the independently verified result `5`. A second turn in the same staging session correctly recalled the edit. A separate authenticated SSE test disconnected immediately after `run_started`, then reattached using the run ID and last sequence; it received 384 further events through a final result with no duplicate sequence. All PR CI checks passed on macOS, Windows, Linux, and the Web preview. The staging API and search are healthy again. ECS quota pressure required temporarily stopping and then restoring the Arcade development pilot; Arcade staging remains stopped as requested.
- Local and Cloud file uploads accept files up to 25 MiB in the UI path. Cloud browser uploads use short-lived, single-use, signed direct-upload tickets to avoid the Next.js body proxy. Local and CLI document reads return bounded chunks with offsets so a large PDF does not consume the entire model context. `cli_search_file` and `search_library_item` find bounded passages and offsets in large workspace and attached/project Library files; repeated workspace PDF reads reuse an in-memory extraction cache. Desktop smoke journeys located and read conclusions near the end of both a long workspace file and an attached Library file. A 2.2 MB, 180-page PDF yielded 691,477 characters in a local extraction stress check; the Cloud extraction default now covers 500 pages and one million characters, and flags a partial extraction.

The read page independently contained the cited section heading and both summarized points. With that QA file deleted, a natural Project follow-up used `listProjectChats` and `readProjectChat` to recover the correct date and decision owner from earlier sessions. - A signed-in Chrome journey against a local Web build and the managed staging API created a chat, showed the sent prompt and working state immediately, opened the session without a loading screen, generated a concise title, and recovered the answer from storage. ## Release blockers

1. **Hosted free inference:** The GPU service has not been deployed or load tested. AWS login was refreshed, a $500 monthly account budget was created, and an eight-vCPU G/VT quota increase for `eu-west-2` is pending. The budget does not stop spending by itself. The gated API now names a pinned official Qwen3 1.7B FP8 candidate, constrains its tool catalog and context estimates, and has 19 passing focused tests. Its quality and actual GPU memory fit remain unverified. A cost guard, service deployment, and staging load test are still required. The free model remains hidden. See [hosted-free-model-service.md](./hosted-free-model-service.md).
2. **Durable long runs:** An API worker restart still interrupts its active agent. The shared store replays events and reports interruption; it does not resume execution on a new worker. A durable worker queue and restart recovery are required for the requested very long-running tasks.
3. **Media model choice:** Chat models are selectable; images offer the starter model plus Q4 and Q8 versions of the same Tiny SD architecture, and accept compatible manually installed checkpoints; speech offers Whisper sizes, SpeechT5 voices, and a downloadable Kokoro voice option. Other image architectures and downloadable video generation models are not complete. Local video generation is not implemented.
4. **Platform coverage:** The image and voice runtime has been exercised on macOS ARM. Windows and Linux image binaries and the packaged app need their own end-to-end checks.
5. **Production verification:** The new Cloud run path has unit checks and a two-replica simulation against real Postgres SQL in PGlite. Authenticated staging CLI coding, session resume, and interrupted SSE reattachment now pass against the managed database and the patched API image. A signed-in local Web browser also exercised real staging storage and in-app navigation, but GPU inference, live token continuation after a reload, the production Web origin, and simultaneous API replicas remain unverified. Staging canaries have repeatedly hit the account's 12-vCPU Fargate quota, even while recently stopped tasks were no longer shown as running. ECR retention has been raised from 30 to 120 images in AWS and the bootstrap templates. An immutable, scanned PR image completed an API-only CloudFormation canary after temporary development capacity was freed; the stack is `UPDATE_COMPLETE`, API health and authenticated route probes pass, and the managed staging database has zero pending migrations. The search service is running and healthy; the access-control image completed its API canary, a later legacy-tool guard reached 100% staging traffic, and the conversation-only mutation guard awaits staging validation. Its CloudFormation `SearchImageUri` parameter still names a deleted image while the actual ECS configuration uses the available `staging-manual-108-search` image. Reconciling that parameter also triggers an API canary through `SearchService.Endpoint`, which exceeds the current 12-vCPU quota. The 16-vCPU request is open; Common Arcade staging remains stopped as requested to preserve capacity. The macOS signing identity is expired, so a production signed Desktop release cannot be published yet. An unsigned packaged macOS candidate passed its launch smoke.
6. **Workspace baseline:** A full API typecheck in this working tree currently fails on unrelated untracked `game-thumbnails` and `common-tool.service.spec` files. The production changes typecheck with those files excluded; resolve or isolate that work before a clean release build.
7. **Dependency triage:** The production lockfile audit still reports four high-severity advisories after the critical, direct-exposure, and compatible transitive patches. The unused Privy provider and its vulnerable `bigint-buffer` dependency have been removed. The remaining paths are `extract-zip` through the API's Puppeteer browser installer (two advisories), and `image-size` through Metro, static Docs MDX processing, and the API's PPTX package (two advisories). The Desktop's direct `extract-zip` runtime path has been removed. The API image skips Puppeteer's installer download and uses a SHA-verified Chrome archive; the final image built in CodeBuild, loaded Sharp and Puppeteer, and ran Chrome successfully. This confirms the browser installer is not needed in that build path, but the remaining image parser paths need their own runtime reachability review before release. PptxGenJS 4.0.1 references `image-size` only inside a commented-out helper; the API derives embedded slide-image dimensions with Sharp before passing data URIs to PptxGenJS. Sources: [image-size JXL/HEIF advisory](https://github.com/advisories/GHSA-5p2g-fcmc-qvqq), [ICNS advisory](https://github.com/advisories/GHSA-w3rx-r6r6-pgpr).
8. **Web capture isolation:** The application proxy now blocks private-address navigation and direct tool discovery, and accepts public IPv4 and IPv6 answers while rejecting DNS sets with any private address. A production VPC egress policy and an authenticated Web-capture journey on the deployed origin are still required. They provide defense if browser code bypasses its configured proxy or if another capture path is introduced.
9. **Retire legacy Goals and Tasks:** Goals and Tasks are deprecated product abstractions and must be removed from the intended experience. The current compatibility repair only prevents an existing Goals 500, unsolicited creation, and unauthorized access while their routes still exist. Inventory API, SDK, scheduler, automation, and stored-record dependencies; migrate scheduled work to a durable run/job design; then remove the Goal/Task tools, routes, UI, and tables with a data migration. Do not build new product flows on these abstractions.

Do not merge or deploy these changes as a complete production release until the blockers above are closed and the exact release artifact passes smoke tests.
