# Build Websites

Deliver a working, polished site rather than setup instructions or an untested code dump.

## Workflow

1. Inspect the brief, source content, brand assets, and any existing project before changing files.
2. Choose `createCodeProject` for a lightweight React experience. Use the persistent computer when the project needs a backend, arbitrary packages, an existing repository, or unrestricted tooling.
3. Establish a clear information hierarchy and visual direction before implementation.
4. Implement the complete related files, including responsive states, empty/error states, and meaningful interactions.
5. Build and publish the project.
6. Use `testCodeProject` or `testComputerBrowser` on the real result. Check desktop and mobile layout, important interactions, console errors, failed network requests, and overflow.
7. Fix, republish, and re-test until clean.

## Quality rules

- Avoid generic template copy and arbitrary gradients.
- Use the supplied brand, content, and imagery deliberately.
- Do not claim a live site exists without a confirmed deployment URL.
- A successful build is not visual QA.
